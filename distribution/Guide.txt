GET STARTED

Download OOT-Remake-Archipelago-0.11.0-alpha.1.exe from project Releases.
Keep this Windows x64 application wherever you prefer. Python and Node.js
are included; normal use needs no console.

Native setup needs your own game version 1.1.1 and working Triforce with
its build tools. Experimental native Hookshot requires version 3.0.1,
original tools and retained build files. No game files or host are supplied.
Obtain your .apootrr file, active room address and any password from the
person generating your multiworld.

1. Choose Set up a room, the player file and game host.
2. Confirm the detected installation or choose its folder.
3. Enter the room address and password, then Install and prepare.
4. Wait for preparation and any host build, then choose Play.
5. Use a save dedicated to this room. The native connection can begin at
   the title screen; delivery waits for a loaded save and suitable control.

Later, choose Play again. Closing the application leaves the native game
and its connection running. Do not run two hosts for the same player slot.

CREATE AND CONFIGURE A ROOM

The organizer needs Archipelago 0.6.7 or later; 0.6.8 has been tested.

1. Choose Create YAML > Install APWorld on the generating computer.
   Select its existing Archipelago installation, then restart AP.
2. Enter the player name and open Settings.
3. Choose Full network for a new room. Standard, Maximum AP and Quick
   start are starting points; edit the supported options as desired.
4. Apply, then Save YAML. Generate and host with Archipelago and all
   players' YAMLs as usual. Give each player their generated player file.

Archipelago still generates and hosts the multiworld. This application
prepares Zelda. Import configuration accepts YAML/JSON and preserves
advanced AP common fields, weighted values and unknown fields. Export can
also write JSON. Cancel in Settings keeps the previous configuration.

Full network uses generation_mode: full_network and full_* settings. Its
defaults create 1,104 real AP checks, including 98 Gold Skulltulas and 64
slots across eight shops. Enabled supported sources use AP placements
instead of separate local randomized rewards. Locations with approximate
access hold filler; progression uses precise access. Dungeon-item rules
still apply. AP can place ordinary progression in other players' games,
without promising identical counts or progression timing for each world.

Legacy retains the previous native OOTRR options and narrower AP catalogue.
Imported old YAMLs keep that engine. It downloads OOTRR 0.8.1 when needed;
full-network preparation uses the bundled engine. Renaming old keys to
full_* does not convert an existing room.

Changing engines or placements needs a new room and fresh save. Updating
or reconnecting cannot change a seed. Existing player files remain readable.
Random? rolls options independently; dependencies still apply. Read each
option's description before randomizing everything.

Experimental adult start plays the native first-pedestal and Rauru prologue
before giving control in the Temple of Time. Both real reward sources run
once. A shuffled Master Sword must be received as its actual item; the
adapted pedestal still permits returning to childhood without it. A new
save and gameplay confirmation are required for this option.

CONNECTION AND DEATHLINK

Connection changes the native address or password. Triforce's Options >
Archipelago and Hookshot's F1/Insert > Gameplay > AP Server / AP Connect
control the same connection. Player and room identity come from the file.

With Zelda closed, Save retains settings for the next start. With the mod
running, Connect/Disconnect controls its live connection. Keep retains a
password without revealing it; Replace stores a new one; Clear removes it.
Windows protects saved passwords for your account. Hookshot's native text
entry is ASCII; use the desktop window for passwords containing accents.

Addresses accept host:port, ws://host:port and wss://host:port.
archipelago.gg uses TLS automatically. 127.0.0.1:38281 is the usual local
address on the computer hosting the server.

Enable death_link in the player settings before generation to share deaths
through the native bridge. Observed paused or busy actions defer incoming
deaths until suitable control resumes. External DeathLink is unavailable.
Not every menu transition or host revision has been tested in-game.

REWARDS AND SAVES

Personal rewards use native models and effects. Remote rewards use the AP
medal and are sent to their owner. An enabled AP source replaces its old
local grant, including quest exchanges. Repeatable refills may remain
after the first AP reward, such as milk from a checked cow.

Remote items sent while Zelda is closed wait on the server and arrive in
order after reconnection. The native bridge commits each grant and received
index together; personal physical rewards have no second network grant.
Save before quitting normally.

Prepared AP history can restore completed locations to an older save.
Personal rewards recover once to that save. Remote locations recover
without resending another player's item. Native rewards outside the AP
catalogue keep their per-save behavior.

Major items use native presentation and turn toward the camera. Small
pickups keep native effects and sounds. Delivery waits while Link is busy,
including crawling, fishing, pause and events. Ammunition without its
equipment gives nothing: no substitute rupee or popup; the index advances.
The entire catalogue and every constrained action have not been manually
played through. Presentation remains an area for regression testing.

ROOMS, BACKUPS, TRACKER AND CHAT

My rooms lists prepared profiles. Rename them, open an external room or
activate a cached native room with Zelda closed. A profile copy of the
player file survives moving the original download. If preparation is
needed, reuse that file in Set up a room. Switching hosts does not transfer
saves or received-item history.

Back up save creates and verifies a copy without editing the original.
Native backups cover profile user data and relevant history; external
backups cover the explicitly chosen save. Passwords are excluded. Open
the folder to retain a copy elsewhere. Automatic restore is not provided.

Archipelago tracker shows known checks. Prepared full-network rooms add
inventory, keys, souls and estimated access from an observed save. Select
a save when there are several. Estimates may wait until saving and remain
informational. The tracker sends no manual checks or planned reward spoilers.

Archipelago chat uses the existing connection. Only Send sends a message.
Recent history is bounded and kept in memory. Native chat creates no second
AP login and does not queue messages for another room.

OTHER PORTS AND EMULATORS — EXPERIMENTAL

This separate window accepts a full-network player file, supported RomFS
folder or NUP, dedicated mods folder and exact host/game executable. A ROM
is optional for launch. progress.sav is optional; selecting it later permits
read-only tracking while the game is closed. Original saves are not moved.

Install and prepare, launch normally, then connect here. Keep this window
open: it owns the external runtime. Tracker and chat share its connection.
Opening a library profile does not connect automatically. Disconnect before
changing installation inputs. Live tracking before the first save requires
verification of the running game's seed.

Seed and receipt-readiness checks guard delivery. Protocol/setup tests do
not establish every port or emulator version. External DeathLink is not
implemented; no Linux executable is packaged. Historical Fritchii tests
proved RomFS loading and the AP title badge only. Native Triforce remains
the established gameplay path. See docs/PORT-COMPATIBILITY.md for evidence.

The external runtime reconciles server-confirmed checks into older saves.
Personal rewards recover once; foreign checks restore completion without
resending. Spent adult trade items are acknowledged quietly. These paths
have local-server and native-resource model tests, not a port playthrough.

UPDATES, LANGUAGE AND HELP

Help > Check for updates checks compatible releases. Include prereleases
includes alpha versions. Signed downloads require Ed25519 authentication
and SHA-256 verification before a separate Install and restart action.
The previous executable is retained; immediate restart failure restores it.
Unsigned historical releases open their normal download page. Updating the
application does not modify games, saves or prepared rooms.

To install mod changes, save and close Zelda, wait for host updates to
finish, then prepare the same player file with the new application.
Data remains under %LOCALAPPDATA%\OOTRR-Archipelago. Native Hookshot uses
hosts\hookshot and external sessions use hosts\external\profiles. Moving
or replacing the executable leaves this data in place.

French game language selects French display text; other languages use
English. Restart Zelda after changing its language. YAML keys stay English;
player names, chat and foreign-game items retain server wording.

Help > Open log opens diagnostics. Licenses and source shows the bundled
notices. Report app/host versions, source location and reproduction steps.
Review logs before sharing them; do not post game files, passwords or
private saves.
