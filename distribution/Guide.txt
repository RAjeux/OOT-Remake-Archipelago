Archipelago · Ocarina of Time Remake · 0.6.1-alpha.1
Alpha for Triforce on Windows x64.
https://github.com/RAjeux/OOT-Remake-Archipelago

Tested with Triforce 0.6.0. Item presentation animations and some camera
movements still need improvement. Hookshot and Fritchii are not supported
by this release's native integration.

Before you start
Prepare Windows x64, Triforce and its build tools, your own version 1.1.1
game dump (including romfs), OOTRR portable 0.8.1, Python 3.11 or later,
and Node.js 22 or 24. No Nintendo game files are included.
Download OOTRR-0.8.1-windows-x64-portable.zip from
https://github.com/ootrando/ootrr/releases/tag/v0.8.1
and unpack it in a separate folder alongside your regular OOTRR installation.
Select this portable folder's ootrr.exe when configuring Archipelago.
The regular app may update to 0.8.2, which changes some native location
identities and cannot build this integration's frozen seed catalogue.
Configuration checks the portable builder's settings protocol before building.
The room generation machine needs Archipelago and the included APWorld.
The APWorld requires Archipelago 0.6.7 or later; direct YAML generation
has been tested with 0.6.8. Use a save dedicated to your Archipelago room.

Create a room
1. Install ootrr_remake.apworld in Archipelago on the generation machine.
2. Run Create-YAML.cmd to prepare Zelda's YAML. Supported OOTRR settings
   and their descriptions are written directly in the file. The repository's
   examples/ directory also provides examples. death_link and
   shuffle_shops and adult_trade_shuffle are explained below.
3. Generate a room with this YAML and the other players' YAML files.
   Obtain your .apootrr player file, then start that room's server.

First installation on the Zelda player's PC
1. Close Zelda and any older client for this save. Extract the entire ZIP.
2. Run Configure-Archipelago.cmd and select your .apootrr player file.
   When prompted, select Triforce's mod directory, ootrr.exe from portable
   version 0.8.1, and the version 1.1.1 game's romfs directory.
   Once installed, the Archipelago mod directory contains archipelago.dll
   beside romfs. Paths are remembered for later configurations.
3. Enter the server address and a password only if the room requires one.
   On the machine hosting the server, the default address is 127.0.0.1:38281.
   archipelago.gg uses wss:// automatically, including saved older ws://
   addresses. Other hosts and local servers retain their chosen transport.
4. The host tools are usually in %LOCALAPPDATA%\Programs\Triforce\tools.
   If asked, select the directory containing host and nx2. The installer
   preserves the original source and reports incompatible host tools.
5. Once configuration is complete, close its console. In Triforce Setup,
   enable Archipelago, then rebuild the game with Build again.
6. Wait for the build to finish and launch Zelda from Triforce.
   The game connects to Archipelago from the title screen.

Later sessions and updates
Double-click Connect-Archipelago.pyw for a separate connection window without
a console. Select a prepared room, enter the server and password, and choose
Save while the game is closed or Connect while its updated AP mod is running.
Closing this window leaves the game's connection running. The window needs
Python with Tkinter (included with the standard Windows Python installer).
It follows the profile's game language and never opens a second AP session.
Other hosts still require a compatible AP gameplay bridge.

Launch Zelda normally from Triforce; the configuration console does not
need to stay open. Open the game's Options screen from the title screen
or the pause menu, then select the Archipelago tab. Enter the server,
set a password if required, and choose Connect. The panel shows connection
status and errors. A controller can enter text using the on-screen keyboard.
Use Disconnect to stop the network connection for the current session.
Automatic connection controls the next game startup; changes are saved
when you choose Connect. The player shown is bound to the prepared mod.
To return to normal play, disable Archipelago in the
launcher and restart the game.
If an update replaces Triforce's tools or executable, let the update finish,
run Configure-Archipelago.cmd again, and rebuild the game. A change to the
mod's native library also requires rebuilding Triforce with its new digest.
Do not configure the mod while the host is updating.
Each new room requires its own .apootrr file and configuration.
Upgrading to 0.5.0-alpha.2 changes the native network library to support
compressed WebSocket connections. Extract the complete updated client ZIP,
configure the same .apootrr again, then use Build again in Triforce Setup.
Existing rooms and saves remain supported; no new seed is needed.
Triforce's Options menu remains available.
Version 0.6.1-alpha.1 updates that native library. Prepare the mod again and
use Build again in Triforce Setup. Existing player files and saves remain
supported. Generate a new room to use the corrected dungeon access rules;
an existing room retains its original placements.
The full adult trade shuffle requires a newly generated room and its own save.

Language
The mod automatically follows the game language selected in Triforce.
French uses French text; other languages fall back to English. No language
option is needed in the YAML. The observer follows the running game's
language. Other players' names, chat, and items from other games keep their
server wording. Configuration tools default to English and may reuse the
known game language. YAML descriptions use English.

Check the connection
The server should show your slot connected while Zelda is at the title.
Observe-Archipelago.cmd displays game notifications and can be closed at
any time. Check its status for the active mod and accepted room connection.
The log is stored at
%LOCALAPPDATA%\OOTRR-Archipelago\<room identifier>\archipelago-jeu.log.
Do not include session or configuration files with public logs.

Chests and received items
A chest containing your own item shows and grants the assigned native item.
A chest containing another player's item shows an AP medal and recipient,
then reports its AP location. The old local reward is not granted as well.
Network locations cover catalogued chests and, when enabled, eight Kokiri
purchases, supported Gold Skulltula drops and adult trade rewards. Other
sources, including freestanding heart pieces, retain OOTRR's local handling and may differ
from the unmodified game.
Items from other worlds are delivered in order while a save is active.
Their effects are native; presentation and some camera movements remain
imperfect in this alpha.
For major received items, Link uses the native turn toward the player
camera before presenting the item. Ordinary pickups keep their central
display and native sounds.
Each grant and its received-item index are committed together. Items sent
while Zelda is closed remain on the server and are recovered after
reconnection and loading a save. Save before quitting normally.
The mod retains checks during an interruption and retries the connection.
After preparing the updated mod, loading an older save also restores its
previously checked AP locations. Your items are granted once to that save;
foreign items restore only the location, without a second send. This covers
AP chests, enabled Kokiri purchases, supported Gold Skulltulas and shuffled
adult trades. Native-local
OOTRR rewards outside that catalogue still follow the selected save and are
not reconstructed from AP history.

If a medal resource cannot be prepared, the room's medaillons-diagnostic.txt
records the error. The chest notification can still show the item's name
and recipient.

The eight Kokiri purchases
Set shuffle_shops: shuffle in Zelda's YAML before generating a new room.
OOTRR shuffles shop goods normally. The eight Kokiri shelves become AP
checks and can sell your own items or another player's items, at their
OOTRR seed prices. Single-player rooms are supported. Your own rewards
use native item models and effects; remote rewards use the AP medal.
Payment and the sold-out display use the game's mechanisms; a completed
purchase reports its AP check. shuffle_shops: off excludes shops from AP.
The native deals_1 through deals_4 and random modes are also available;
shops outside the Kokiri catalogue retain their native local rewards.
The old kokiri_shop_checks test option was removed. Replace it in existing
YAML files; already generated rooms keep their original placements.
One purchase has been tested in the game, including the other player's
receipt and the sold-out state after reloading. All eight shelves have
automated coverage, but they have not all been purchased in the game.

Adult trade shuffle
Set adult_trade_shuffle: true and shuffle_rewards: supported before generating
a new room. The eleven adult trade rewards become AP checks, including Anju's
first gift and Biggoron's final reward. They grant only the assigned AP item;
the old quest reward is not added as a bonus. The ten quest items are shuffled
throughout the multiworld, starting with an already hatched Pocket Cucco.
Talk to the appropriate NPC while owning their requested item. Items hidden
behind another trade item in the shared menu slot are accepted automatically.
Only the requested item is consumed; your other trade items remain available.
Wake Talon before returning the Pocket Cucco to Anju. Trade items no longer
expire, and Biggoron's final exchange does not require waiting three days.
The former additive shuffle_trade_checks control is not accepted in new
YAMLs. Existing generated rooms keep their original behavior.

Gold Skulltulas and the other OOTRR settings
shuffle_skulltulas accepts off, pinned and matched. pinned adds 44 firmly
identified native locations; matched adds the supported researched matches.
The reward must be collected: killing a Skulltula or receiving a token does
not check its location. matched normally has 76 checks, or 77 with
plant_beans: true or native starting Magic Beans. The 23 uncertain matches
keep their native local handling. Local bottle refills are not placed on
AP Skulltulas because their pickup cannot wait for an empty bottle.
Use the complete matching client ZIP and generate a new room for these IDs.

The YAML includes 93 native OOTRR settings, the adult trade extension and
DeathLink. Supported
NPCs, songs, cows, ground pickups, destructibles, dungeon entrances and
prices can be randomized natively. Those sources stay local unless they
belong to the explicit AP chest/shop/Skulltula/trade catalogue. Experimental
breakable sources stay broken; collect their drop before leaving or it
can be lost. The repository's docs/SETTINGS-COMPATIBILITY.md compares all
118 native settings and explains the 25 omitted options. Private in-game tests
verified consecutive personal, foreign and rupee pickups, plus older-save
recovery, using real pickup packs placed in a private scene. They do not cover
every original Skulltula site or confirm the foreign medal's 3D visibility.

Set bridge: open for a bridge that appears on approach without dungeon rewards.
Leave bridge_rewards at its default 9 or set it to 0; this choice uses an
effective threshold of 0. Set bridge: dungeons to choose another reward count.

DeathLink
Set death_link: true in Zelda's YAML and enable DeathLink in the other
participating games before generating the room.
Link's death is sent to connected DeathLink players. A received death kills
Link while a save is active without sending a second death back.
During a purchase or item receipt, it waits for the event to finish so the
transaction can complete. The title and loading screens do not retain
a pending death for the next active save.
Both directions have been tested on Triforce 0.6.0, including a natural
local death. Deferral during an event is covered by simulated tests;
it has not been confirmed in every in-game scene.

Older rooms
Existing .apootrr files retain their room behavior and saves. Do not edit
an old room's flags to convert it to a new mode. To use this alpha's mode
or different settings, generate a new room with this release's APWorld
and configure its new .apootrr file.
The previous French command filenames remain as compatibility aliases.

Report a problem
Include the release version, Triforce version, game context, and steps that
reproduce the issue. Player files and logs may contain participant names;
review their content before posting them publicly. Do not attach game files
or saves. The repository README documents the code, tests, limitations,
and credits. Automated tests do not replace in-game validation.
