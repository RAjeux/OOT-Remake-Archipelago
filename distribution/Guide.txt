The discontinued 0.11/0.12 Full experiment is not the current release,
even though its version number is higher. Its player files use a different
format and are not converted. Export a fresh YAML in the current editor,
generate a new room with the current APWorld and keep old Full saves separate.
Native 0.10 rooms remain supported.

Before you start
You need Windows x64, your own game files at version 1.1.1, and a working
Triforce installation with its build tools. First build and launch the base
game following the official Triforce instructions:
https://triforceproject.com/#install

Hookshot is experimental and requires a completed 3.0.1 installation with
its matching original tools and retained build files. Other revisions are
rejected. Official source/setup and the pinned release are available at:
https://github.com/ItsNotRexed/Hookshot
https://github.com/ItsNotRexed/Hookshot/releases/tag/v3.0.1
For a first installation, use Triforce for this integration.

Keep the downloaded launcher EXE in a convenient folder. Python, Node.js,
the AP client and APWorld are included. The compatible OOTRR 0.8.1 builder
is downloaded when first needed. No separate randomizer installation is
required. No Nintendo game files are included.

Files and roles
- .yaml: a player's settings BEFORE generation; send it to the organizer.
- ootrr_remake.apworld: the generator's custom game integration. The organizer
  installs it using this OOT Remake launcher's Install APWorld action.
- .apootrr: generated Zelda data for ONE player slot and room. Select your
  own file in Set up a room. It is not a YAML, ROM or APWorld.
- The generated room ZIP and .archipelago server data are for the organizer.

A player joining a generated room only needs the launcher, compatible game,
their .apootrr and the room address/password. They do not need to install
Archipelago or an APWorld separately.

Each Zelda player: choose settings before generation
1. Choose Create YAML, enter a unique player name, then Choose settings.
2. Search in English, French or by YAML key. Review the explanations,
   including inactive sub-options and their requirements. DeathLink is here.
3. Apply the settings, Save YAML and send that file to the organizer.
Changing a YAML later does not change an existing room.

To reuse an old configuration, choose Create YAML -> Import YAML, open its
.yaml/.yml, then Choose settings. The name and compatible settings are loaded.
Additional AP options and weighted selections are kept. Use Replace on an
"Imported value kept" setting to change it. Save YAML proposes a separate
-modified.yaml copy, preserving the original. Import details lists compatibility
changes; unsupported old options must be reviewed. New configuration starts
over with the current defaults. Comments and formatting are regenerated.

Organizer: generate and host
1. Install official Archipelago, including its generator, from:
   https://github.com/ArchipelagoMW/Archipelago/releases
   This APWorld requires 0.6.7 or later; generation is tested with 0.6.8.
2. In this OOT Remake launcher, choose Install APWorld and select your
   Archipelago installation. Use the Windows account that will generate.
   This also installs its generation runtime. Restart Archipelago.
3. Collect every player's YAML and install other required custom worlds.
   Put the YAMLs for this room in Archipelago's Players folder and generate
   locally with Generate / ArchipelagoGenerate.exe. The public website's
   generator does not include this custom APWorld.
4. Host the generated output locally or upload it to Archipelago hosting.
5. Give each Zelda player THEIR generated .apootrr, the address and any
   room password. They can now follow Prepare and play below.
The launcher does not generate or host rooms. The official AP guide covers
local generation and both hosting routes:
https://archipelago.gg/tutorial/Archipelago/setup_en

Prepare and play
Finish any host update, then close Zelda and its setup/builder application.
1. Open this launcher and choose Set up a room.
2. Select YOUR .apootrr and Game host. Choose the game folder if it was not
   detected. The application checks the game files and tools before setup.
3. Enter the room address and a password only if the room requires one.
   Choose Install and prepare.
4. Wait for preparation and any necessary game build to finish. Progress
   appears in the same window; no console is needed.
5. Choose Play. The game connects from the title screen. Use a dedicated
   new save for a new room, or that room's existing save when continuing.
For later sessions, open the same launcher and choose Play. Closing it
while playing leaves Zelda and its Archipelago connection running.

The sidebar contains Home, Set up a room, Create YAML, Connection,
Install APWorld and Help. Ctrl+1/2/3 opens the three main pages. Keyboard
focus scrolls form fields into view; the settings editor supports Ctrl+F.

Change the connection
Choose Connection in the launcher, or Options > Archipelago in Triforce.
Hookshot provides F1/Insert > Gameplay > AP Server / AP Connect. Run one
host at a time for the same AP slot. These interfaces control the same
prepared room and connection. Hookshot's native editor accepts ASCII;
use the desktop window for passwords with accents or other characters.
With Zelda closed, Save remembers the connection for next startup. With
the mod running, Connect and Disconnect apply live. Automatic connection
starts enabled; preparing an existing room retains its saved preference.

Keep retains a saved password without displaying it, Replace saves a new
one, and Clear removes it. Passwords are protected for the current Windows
account. Room and player identity come from the prepared player file.

Addresses accept host:port, ws://host:port or wss://host:port.
archipelago.gg uses TLS automatically. 127.0.0.1:38281 means a server on
YOUR OWN PC; for a remote room, use the organizer's address.

Updates and saved data
Version 0.10.4-alpha.4 fixes a black screen and missing control after starting
a new game with the dungeon-key tracker. Close Zelda and prepare the same
player file again when requested. The previous menu-memory fix is retained.
Your existing room, settings, item placements and save remain supported.
This version retains alpha 2's launcher replacement and versioned EXE fix.
After a successful update, the new EXE uses its release filename in the same
folder. The previous EXE is kept in private update data under LocalAppData
for rollback. A shortcut targeting the old filename may need retargeting.
The normal update action handles older 0.10.4 launchers; no manual rename,
new room, save or APWorld installation is required for this patch.

Version 0.10.4 adds reviewed sources, access rules and optional gameplay
settings for new rooms. Existing native 0.10 rooms, player files, YAMLs and
saves remain supported. Download the current launcher once if your old app
lacks updates.
Then use Help > Check for launcher updates, Update available, download,
and Install and restart. Normal Play stays available if checking fails.

The organizer can opt into APWorld replacement when its installed file
differs. The new launcher installs its matching APWorld/runtime after restart.
Previous copies are backed up; renamed duplicate copies of the same package
are removed from the active directory. Other games are kept. Restart
Archipelago before generating. Updating an APWorld does not reroll a room.

Profiles, connection settings, tools and saves are kept under
%LOCALAPPDATA%\OOTRR-Archipelago, outside the EXE. Moving or replacing the
launcher keeps them. Hookshot has a separate hosts\hookshot namespace;
switching hosts does not transfer a save or its received-item history.

When the launcher detects older prepared resources, close Zelda and its
builder and prepare the SAME compatible native 0.10 .apootrr with the SAME
save. No new room or YAML is needed for this kind of resource update.
The 0.10.2 native consumable packs grant exactly 10/20 bombs, 30 arrows/seeds
and 5/10 nuts. Already acknowledged packs are not compensated retroactively.

A new configuration, expanded checks or full adult-trade shuffle requires
a newly generated room and dedicated save. Existing rooms keep their
original settings and placements. Full 0.11/0.12 files are not converted.

Current compatibility and help
Triforce 0.8.3 has real title-screen connection and reconnect evidence, plus
a private current-room Bow/quiver and five-rupee receipt check. Earlier 0.10
gameplay evidence and host checks are documented separately.
Hookshot 3.0.1 remains experimental; Fritchii has no AP gameplay backend.
Longshot is an internal prototype, not a supported launcher host.
The installer does not support Linux or other emulators. Current setup
instructions and historical evidence are separate in:
https://github.com/RAjeux/OOT-Remake-Archipelago/blob/v0.10.4-alpha.4/docs/PORT-COMPATIBILITY.md

If a player file is rejected, check its extension, slot, room and native
0.10 compatibility. If Archipelago cannot find Ocarina of Time Remake,
install the APWorld into the correct generator installation and restart AP.
Help > Open log gives details of preparation and connection failures.

Items and checks
Your own AP rewards use native item models and effects. Another player's
item uses the AP medal and is sent to its recipient. The old local reward
is replaced. In new rooms, every supported source selected by the native
randomizer becomes an AP check, including enabled NPCs, songs, ground items,
destructibles and all 64 purchases in an enabled shop shuffle. Old rooms
keep their own catalogue, purchases and native-local rewards.

Items received while Zelda is closed remain on the server. They arrive
in order after reconnecting and loading a save. Each grant is committed
with its received-item index. Save before quitting normally.

With a prepared all_locations room using personal physical rewards,
loading an older save also restores previously checked AP locations.
Your rewards are restored once to that save. Another player's location
is restored without sending its reward again. Fixed or unselected native
rewards follow the selected save. Older rooms retain any native-local rewards
which were outside their own generated AP catalogue.

Supported settings
The shared schema exposes 94 native OOTRR settings and 36 integration
controls: 130 controls in total. New options require a newly generated room.
In particular:
- Optional 0.10.4 controls add medallion goals, Skulltula timing, key tracking,
  travel/minigame shortcuts, native Ice Traps, colours, music/SFX and personal
  item plando. New difficulty settings are experimental; known broken enemy
  size and roaming Volvagia controls are unavailable.
- Every enabled shuffle_shops mode turns all 64 purchases in eight shops
  into AP checks. shuffle mixes native stock; deals_1 through deals_4 and
  random_deals change the native pool and special-deal price layout before
  AP fills the checks. No mode forces a recipient. Plain random / Random?
  chooses a whole shop mode, which may be Off.
- Gold Skulltulas: All 100 native sites uses shuffle_skulltulas: matched.
  The 44-site subset uses pinned. Collect the drop to complete a check.
  The 23 uncertain sites retain their filler-only restrictions; they cannot
  contain progression or Zelda tokens, but remain AP checks.
- shops_always_open keeps the eight item shops and the Mask Shop open by
  day and night. Quest locks remain; minigames keep their normal hours.
- Ground pickups and heart pieces uses shuffle_freestanding_items.
  Off and Pieces both shuffle supported heart pieces in this engine.
  All adds rupees and recovery hearts; Dungeons or Overworld limits those
  extra pickups by area. The three dedicated heart-piece chests follow this
  setting too; other chests and NPC rewards have separate controls.
- adult_trade_shuffle: true with shuffle_rewards: supported puts ten
  quest items in the multiworld and replaces eleven trade rewards with AP
  items. An exchange consumes only its requested item. Wake Talon before
  returning the Pocket Cucco to Anju; expiry and the final wait are disabled.
- shuffle_master_sword: true puts the Master Sword in the multiworld.
  Its first pedestal grant becomes an AP reward. Rauru's reward and native
  time travel remain separate. The default false keeps the native sword.
  This choice requires a newly generated room and a new save.
- bridge: open opens the bridge on approach. Leave bridge_rewards at its
  default 9 or use 0; this choice uses an effective threshold of zero.
- The forest is Closed by default. Open under Deku Tree and forest access
  removes Mido's opening requirement and opens the forest exit too.
- Skip introduction automatically skips the opening movie and Link waking.
  Manual cutscene skipping unlocks the existing skip action; it does not
  automatically skip every cinematic. The 0.10 behavior is retained.
- death_link: true shares deaths with other participating games. A received
  death waits for normal control after an observed pause or constrained action.

Network items and restored AP locations wait while Link crawls, fishes,
climbs, swims, fights, uses an item, plays an event or has the game paused.
Unknown player actions defer delivery too. A fishing rod remains protected
between casts. Missing ammunition equipment consumes that AP reward without
giving ammunition, equipment, a substitute rupee or a pickup animation.

DeathLink retains a death across a long pause once the native bridge has
observed that pause. A menu that stops every Link callback before pause is
observed still needs an in-game check; see docs/DELIVERY-SAFETY.md.

Random? rolls each field independently. Inactive sub-options are ignored:
for example, a random Fixed Price has no effect when the price mode is Cheap.
Active settings still follow their documented dependencies, so selecting
Random? everywhere does not guarantee a valid combination.

Every selected supported source becomes an AP check in new rooms, including
enabled songs, NPCs, cows, ground items and destructibles. Fixed/unselected
rewards stay native. New 0.10.4 rooms have 185 checks by default; tested broad
coverage reaches 1,229 including the optional Master Sword. Selected options
determine the count. Old player files keep their original catalogue.
Generate a new room and use a dedicated new save for the expanded checks.

Breaking a shuffled container does not complete its check. An uncollected
source can be tried again after reloading the area; collected sources stay
completed. A native guard keeps 35 possible sources filler-only, including
the 23 uncertain Skulltulas. They cannot hold progression from any game or
Zelda tokens. This does not remove their AP checks.

AP has no general Zelda recipient quota. Explicit dungeon-only, song-only,
end-of-dungeon and LACS settings still constrain the final placements.
Keysanity permits keys in other games; compatible songs and dungeon rewards
can cross between Zelda players. Cheap merchant prices deliberately charge
10 rupees for every purchase, including each bean; Vanilla retains the
increasing bean prices.
See docs/SETTINGS-COMPATIBILITY.md in the repository for all 118 native
settings and the reasons for the 25 omitted controls.

Language and current limits
The application and mod follow the game language: French uses French text,
and other languages fall back to English. YAML comments use the app language;
keys remain stable. Other players' names and items from other games keep their server
wording. Restart Zelda after changing its language in Triforce.

The 0.10 baseline has gameplay evidence with Triforce 0.6.0. This update
retains its title/cinematic behavior. Item presentation and some camera
movements can still need improvement. Automated real AP generation includes
solo rooms, Zelda with Dark Souls III, and Zelda with Bloodborne and Dark
Souls Remastered. The expanded catalogue has not been manually completed.
Hookshot 3.0.1 remains experimental; Fritchii has no AP gameplay backend.

Help and credits
Help > Open log opens the application log. Help > Licenses and source
provides the bundled notices and corresponding-source information.
These are optional; they are not part of normal setup or play.

When reporting an issue, include the application version, Triforce version,
location and steps to reproduce it. Review logs for participant names before
posting them publicly. Do not attach game files or saves.
