Archipelago · Ocarina of Time Remake · 0.2.1-alpha.2
Alpha for Triforce on Windows x64.
https://github.com/RAjeux/OOT-Remake-Archipelago

Tested with Triforce 0.6.0. Item presentation animations and some camera
movements still need improvement. Hookshot and Fritchii are not supported
by this release's native integration.

Before you start
Prepare Windows x64, Triforce and its build tools, your own version 1.1.1
game dump (including romfs), OOTRR portable 0.8.1, Python 3.11 or later,
and Node.js 22 or 24. No Nintendo game files are included.
The room generation machine needs Archipelago and the included APWorld.
The APWorld requires Archipelago 0.6.7 or later; direct YAML generation
has been tested with 0.6.8. Use a save dedicated to your Archipelago room.

Create a room
1. Install ootrr_remake.apworld in Archipelago on the generation machine.
2. Run Create-YAML.cmd to prepare Zelda's YAML. Supported OOTRR settings
   and their descriptions are written directly in the file. The repository's
   examples/ directory also provides examples. death_link and
   kokiri_shop_checks are explained below.
3. Generate a room with this YAML and the other players' YAML files.
   Obtain your .apootrr player file, then start that room's server.

First installation on the Zelda player's PC
1. Close Zelda and any older client for this save. Extract the entire ZIP.
2. Run Configure-Archipelago.cmd and select your .apootrr player file.
   When prompted, select Triforce's mod directory, ootrr.exe from portable
   version 0.8.1, and the version 1.1.1 game's romfs directory.
   Once installed, the Archipelago mod directory contains archipelago.dll
   beside romfs. Paths are remembered for later configurations.
3. Enter the server address and a password only if the room requires one.
   On the machine hosting the server, the default address is 127.0.0.1:38281.
4. The host tools are usually in %LOCALAPPDATA%\Programs\Triforce\tools.
   If asked, select the directory containing host and nx2. The installer
   preserves the original source and reports incompatible host tools.
5. Once configuration is complete, close its console. In Triforce Setup,
   enable Archipelago, then rebuild the game with Build again.
6. Wait for the build to finish and launch Zelda from Triforce.
   The game connects to Archipelago from the title screen.

Later sessions and updates
Launch Zelda normally from Triforce; the configuration console does not
need to stay open. To return to normal play, disable Archipelago in the
launcher and restart the game.
If an update replaces Triforce's tools or executable, let the update finish,
run Configure-Archipelago.cmd again, and rebuild the game. A change to the
mod's native library also requires rebuilding Triforce with its new digest.
Do not configure the mod while the host is updating.
Each new room requires its own .apootrr file and configuration.

Language
The mod automatically follows the game language selected in Triforce.
French uses French text; other languages fall back to English. No language
option is needed in the YAML. The observer follows the running game's
language. Other players' names, chat, and items from other games keep their
server wording. Configuration tools default to English and may reuse the
known game language. YAML descriptions use English.

Check the connection
The server should show your slot connected while Zelda is at the title.
Observe-Archipelago.cmd displays game notifications and can be closed at
any time. Check its status for the active mod and accepted room connection.
The log is stored at
%LOCALAPPDATA%\OOTRR-Archipelago\<room identifier>\archipelago-jeu.log.
Do not include session or configuration files with public logs.

Chests and received items
A chest containing your own item shows and grants the assigned native item.
A chest containing another player's item shows an AP medal and recipient,
then reports its AP location. The old local reward is not granted as well.
Only catalogued chests and the eight optional Kokiri purchases are network
locations. Some local rewards outside AP, including freestanding heart
pieces, retain OOTRR's handling and may differ from the unmodified game.
Items from other worlds are delivered in order while a save is active.
Their effects are native; presentation and some camera movements remain
imperfect in this alpha.
For major received items, Link uses the native turn toward the player
camera before presenting the item. Ordinary pickups keep their central
display and native sounds.
Each grant and its received-item index are committed together. Items sent
while Zelda is closed remain on the server and are recovered after
reconnection and loading a save. Save before quitting normally.
The mod retains checks during an interruption and retries the connection.

If a medal resource cannot be prepared, the room's medaillons-diagnostic.txt
records the error. The chest notification can still show the item's name
and recipient.

The eight Kokiri purchases
Set kokiri_shop_checks: true in Zelda's YAML before generating a new room.
This prepares all eight native shop shelves and requires at least two
players. Each shelf sells another player's item once, at its OOTRR seed
price. Payment and the sold-out display use the game's mechanisms; a
completed purchase reports its AP check.
One purchase has been tested in the game, including the other player's
receipt and the sold-out state after reloading. All eight shelves have
automated coverage, but they have not all been purchased in the game.

DeathLink
Set death_link: true in Zelda's YAML and enable DeathLink in the other
participating games before generating the room.
Link's death is sent to connected DeathLink players. A received death kills
Link while a save is active without sending a second death back.
During a purchase or item receipt, it waits for the event to finish so the
transaction can complete. The title and loading screens do not retain
a pending death for the next active save.
Both directions have been tested on Triforce 0.6.0, including a natural
local death. Deferral during an event is covered by simulated tests;
it has not been confirmed in every in-game scene.

Older rooms
Existing .apootrr files retain their room behavior and saves. Do not edit
an old room's flags to convert it to a new mode. To use this alpha's mode
or different settings, generate a new room with this release's APWorld
and configure its new .apootrr file.
The previous French command filenames remain as compatibility aliases.

Report a problem
Include the release version, Triforce version, game context, and steps that
reproduce the issue. Player files and logs may contain participant names;
review their content before posting them publicly. Do not attach game files
or saves. The repository README documents the code, tests, limitations,
and credits. Automated tests do not replace in-game validation.
