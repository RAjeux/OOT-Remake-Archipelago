OOT Remake Archipelago · 0.7.0-alpha.1
One application for Triforce on Windows x64.
https://github.com/RAjeux/OOT-Remake-Archipelago

Before you start
Download OOT-Remake-Archipelago-0.7.0-alpha.1.exe from the project releases.
Python and Node.js are included. The compatible OOTRR 0.8.1 builder is
downloaded automatically when first needed; an internet connection is
required for that download. No separate runtime or randomizer installation
is needed.

You supply a working Triforce installation with its build tools and your own
version 1.1.1 game files. Obtain your .apootrr player file and the address
of its active Archipelago room. No Nintendo game files are included.

Prepare and play
1. Open the application and choose Set up a room.
2. Select your .apootrr player file. Triforce is detected when possible;
   choose its game folder if the application cannot find it.
3. Enter the room address and a password only if the room requires one.
   Choose Install and prepare.
4. Wait for preparation and any necessary Triforce build to finish.
   Progress appears in the same window; no console is needed.
5. Choose Play. The game connects from the title screen.
   Use a save dedicated to this room.

For later sessions, open the same application and choose Play. Closing it
while playing leaves Zelda and its Archipelago connection running.

Change the connection
Choose Connection in the application, or open Options > Archipelago in
Zelda. Both interfaces control the same prepared room and game connection.
With Zelda closed, Save remembers the address and password for the next
startup. With the mod running, Connect and Disconnect apply to the live
connection. Automatic connection is enabled by default.

In the desktop connection window, Keep retains the saved password without
showing it, Replace saves a new one, and Clear removes it. Passwords are
protected for the current Windows account. The room and player come from
the prepared player file; use Set up a room for a different .apootrr file.

Addresses accept host:port, ws://host:port or wss://host:port.
archipelago.gg uses TLS automatically. Local servers keep their selected
transport; 127.0.0.1:38281 is the usual address on the hosting PC.

Create a room
The same application provides Create YAML for the room's organizer.
1. Choose Install APWorld and select the existing Archipelago installation
   on the computer that will generate the room. Restart Archipelago.
2. Enter your player name and choose Save YAML. The file contains all
   supported settings and their descriptions. Edit these before generation.
3. Generate and host the room with Archipelago and the other players' YAML
   files as usual, then distribute each player's generated file.

Room generation and hosting remain in Archipelago. The application does not
start a server or generate a multiworld. The APWorld requires Archipelago
0.6.7 or later; generation has been tested with 0.6.8.

Updates and saved data
Room profiles, connection settings, downloaded tools and saves are stored
under %LOCALAPPDATA%\OOTRR-Archipelago. They remain available when the
application executable is moved, replaced or closed.

Close Zelda before preparing a mod. Let any Triforce update finish, then
use Set up a room in the new application with the same .apootrr file.
Existing saves and profiles are preserved. The application rebuilds the
game when necessary. Your normal OOTRR installation is left in place;
the compatible builder is kept separately in the application's data folder.

Each new room needs its own player file and dedicated save. Existing rooms
keep their original settings and placements. Generate a new room for the
corrected dungeon access rules introduced in 0.6.1 or to enable the full
adult trade shuffle. Reconnecting does not change an old room's placements.

Items and checks
Your own AP rewards use native item models and effects. Another player's
item uses the AP medal and is sent to its recipient. The old local reward
is replaced. Network checks cover the catalogued chests and, when enabled,
eight Kokiri purchases, supported Gold Skulltulas and eleven adult trades.
Other shuffled sources retain OOTRR's native local handling.

Items received while Zelda is closed remain on the server. They arrive
in order after reconnecting and loading a save. Each grant is committed
with its received-item index. Save before quitting normally.

With a prepared all_locations room using personal physical rewards,
loading an older save also restores previously checked AP locations.
Your rewards are restored once to that save. Another player's location
is restored without sending its reward again. Native-local rewards outside
the AP catalogue continue to follow the selected save.

Supported settings
The YAML exposes 93 native OOTRR settings, the adult trade extension and
DeathLink. In particular:
- shuffle_shops: shuffle adds eight Kokiri purchases to the AP pool;
  each can contain your own item or another player's item.
- shuffle_skulltulas: pinned enables 44 identified checks. matched enables
  76 supported checks, or 77 with supported planted or starting beans.
  Collect the reward to complete its check. Uncertain sites stay local.
- adult_trade_shuffle: true with shuffle_rewards: supported puts ten
  quest items in the multiworld and replaces eleven trade rewards with AP
  items. An exchange consumes only its requested item. Wake Talon before
  returning the Pocket Cucco to Anju; expiry and the final wait are disabled.
- bridge: open opens the bridge on approach. Leave bridge_rewards at its
  default 9 or use 0; this choice uses an effective threshold of zero.
- death_link: true shares deaths with other participating games. A received
  death waits for an active purchase or item receipt to finish.

Supported native-local shuffles include songs, NPC rewards, cows, ground
items, destructibles, dungeon entrances and prices. Experimental breakable
sources stay broken; collect their drop before leaving.
See docs/SETTINGS-COMPATIBILITY.md in the repository for all 118 native
settings and the reasons for the 25 omitted controls.

Language and current limits
The application and mod follow the game language: French uses French text,
and other languages fall back to English. YAML keys and descriptions use
English. Other players' names and items from other games keep their server
wording. Restart Zelda after changing its language in Triforce.

Native gameplay has been tested with Triforce 0.6.0. Item presentation and
some camera movements can still need improvement. Automated checks cover
more sources than have been played manually; every option combination and
every original Skulltula site has not been completed in the game.
Hookshot and Fritchii are not supported by this release's native installer.

Help and credits
Help > Open log opens the application log. Help > Licenses and source
provides the bundled notices and corresponding-source information.
These are optional; they are not part of normal setup or play.

When reporting an issue, include the application version, Triforce version,
location and steps to reproduce it. Review logs for participant names before
posting them publicly. Do not attach game files or saves.
